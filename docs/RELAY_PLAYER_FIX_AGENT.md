## FIX 1 — Early Relay Connection (Eliminate Slow Connect on Server Start)

### Root Cause
`RelayManager` currently opens the socket pool *after* the Minecraft server process is fully
booted and `[Server thread/INFO]: Done` is detected in the console. This means the user waits
for: JVM launch → Paper boot (~15–30 s) → relay connect (~2–5 s) sequentially.
The relay connect must happen in parallel with the server boot.

### Changes

#### `ServerHostService.kt`
- In `onStartCommand` (or wherever the server start sequence begins), call
  `relayManager.initPool()` **immediately** — before or at the same time as launching the JVM.
  Do NOT wait for the `"Done ("` or `"For help, type"` log line.
- Launch it concurrently on `Dispatchers.IO`:

```kotlin
// In onStartCommand or startServer():
serviceScope.launch(Dispatchers.IO) {
    relayManager.initPool()   // ← fires immediately, parallel to JVM boot
}
startMinecraftProcess()       // ← JVM launch, runs at the same time
```

- Find and **remove** any existing call to `relayManager.initPool()` inside the log-parsing
  callback that fires on `"Done ("` or similar server-ready strings.

#### `RelayManager.kt`
- Add a retry loop inside `initPool()` with exponential backoff (max 5 attempts):

```kotlin
private val _isPoolReady = MutableStateFlow(false)
val isPoolReady: StateFlow<Boolean> = _isPoolReady.asStateFlow()

suspend fun initPool() {
    _isPoolReady.emit(false)
    val backoffMs = longArrayOf(2000, 4000, 8000, 16000, 30000)
    repeat(5) { attempt ->
        try {
            buildSocketPool()          // existing pool creation logic
            _isPoolReady.emit(true)
            return
        } catch (e: Exception) {
            if (attempt < 4) delay(backoffMs[attempt])
        }
    }
    _isPoolReady.emit(false)           // all retries exhausted
}
```

- Keep existing 10-socket pool logic and port assignment unchanged.

#### HomeScreen / ServerCard composable
Observe `relayManager.isPoolReady` and show a small status chip below the server address:
- `false` while server is starting → amber chip "Relay connecting…"
- `true` → green chip "Relay ready" that auto-dismisses after 3 s
- Stays `false` after all retries → red chip "Relay unavailable — tap to retry"
  with `onClick { scope.launch { relayManager.initPool() } }`

## FIX 2 — Auto-Download Floodgate Alongside Geyser

### Why This Is Needed
Without Floodgate, Geyser assigns Bedrock players a **random UUID every session**. The server
treats them as a new player each time → inventory wiped on every rejoin. Floodgate gives each
Bedrock account a **stable, consistent UUID** derived from their Xbox account, so the server
saves and restores their playerdata (inventory, XP, health) correctly across sessions — exactly
like Java players.

### Changes

#### Server setup code (wherever Geyser JAR is downloaded — likely `ServerHostService.kt`,
#### `PluginManager.kt`, or a dedicated `ServerSetupManager.kt`)

Find the block that downloads `Geyser-Spigot.jar` and add Floodgate download immediately after:

```kotlin
object FloodgateInstaller {

    private const val FLOODGATE_API =
        "https://download.geysermc.org/v2/projects/floodgate/versions/latest/builds/latest/downloads/spigot"

    suspend fun ensureInstalled(pluginsDir: File) {
        val jar = File(pluginsDir, "floodgate-spigot.jar")
        if (jar.exists()) return          // already installed, skip

        withContext(Dispatchers.IO) {
            val bytes = URL(FLOODGATE_API).readBytes()
            jar.writeBytes(bytes)
        }
    }
}
```

Call this in the same place Geyser is set up, right after the Geyser JAR is confirmed present:

```kotlin
// After Geyser JAR is downloaded/verified:
FloodgateInstaller.ensureInstalled(pluginsDir)
```

#### Floodgate config — write defaults on first install
After downloading `floodgate-spigot.jar`, check if `plugins/floodgate/config.yml` exists.
If not, create it so Floodgate works out of the box without needing the server to boot once first:

```kotlin
fun writeFloodgateConfig(pluginsDir: File) {
    val configDir = File(pluginsDir, "floodgate")
    configDir.mkdirs()
    val config = File(configDir, "config.yml")
    if (!config.exists()) {
        config.writeText("""
            # Floodgate config — auto-generated by PocketCraft
            prefix: "."
            disconnect:
              invalid-key: "Please connect through the official PocketCraft server."
            player-link:
              enabled: true
              allowed: true
              enable-global-linking: true
        """.trimIndent())
    }
}
```

The `prefix: "."` means Bedrock players appear in-app with a `.` before their username
(e.g. `.Steve`) — used in Fix 3 to tag them as Bedrock in `PlayerDataManager`.

## FIX 3 — Full Bedrock Player Persistence (Same as Java Players)

Now that Floodgate gives Bedrock players stable UUIDs, treat them identically to Java players
in `PlayerDataManager`. There is NO special Bedrock exclusion from disk save/load.

### Changes

#### `PlayerDataManager.kt`

**Step 1 — Tag Bedrock players for UI purposes only (not for exclusion).**
Add `isBedrock` to `PlayerEntry` — used only to show a controller badge on the card,
not to skip persistence:

```kotlin
data class PlayerEntry(
    val uuid: String,
    val username: String,
    val isBedrock: Boolean = false,   // true if username starts with "."
    // ... existing fields (health, inventory, location, etc.)
)
```

Detect at join time:
```kotlin
val isBedrock = username.startsWith(".")   // Floodgate prefix
```

**Step 2 — Persist ALL players to disk equally.**
Save everyone — no Bedrock filter:

```kotlin
fun savePlayersToDisk() {
    val allPlayers = playerMap.values.toList()
    // serialize and write allPlayers
}
```

**Step 3 — Load ALL players from disk on startup.**
Restore everyone — no Bedrock filter:

```kotlin
fun loadPlayersFromDisk(): List<PlayerEntry> {
    return readFromDisk()
}
```

**Step 4 — Split active vs session players for correct card visibility.**

```kotlin
// Players currently online (drives the green dot badge)
private val _activePlayers = MutableStateFlow<List<PlayerEntry>>(emptyList())
val activePlayers: StateFlow<List<PlayerEntry>> = _activePlayers.asStateFlow()

// All players who joined this session (card persists after disconnect/server stop)
private val _sessionPlayers = MutableStateFlow<List<PlayerEntry>>(emptyList())
val sessionPlayers: StateFlow<List<PlayerEntry>> = _sessionPlayers.asStateFlow()

fun onPlayerJoin(entry: PlayerEntry) {
    _activePlayers.update { it + entry }
    if (_sessionPlayers.value.none { it.uuid == entry.uuid }) {
        _sessionPlayers.update { it + entry }
    }
    savePlayersToDisk()
}

fun onPlayerLeave(uuid: String) {
    _activePlayers.update { it.filter { p -> p.uuid != uuid } }
    // sessionPlayers keeps the entry — card stays, dot goes grey
}

fun onServerStop() {
    _activePlayers.update { emptyList() }
    // do NOT clear sessionPlayers — cards remain with "Last session" label
    savePlayersToDisk()
}

fun onServerStart() {
    _activePlayers.update { emptyList() }
    _sessionPlayers.update { emptyList() }   // fresh session
    loadPlayersFromDisk()                     // restore previous player cards from disk
}
```

#### Players screen composable
- Observe `sessionPlayers` for the list (not `activePlayers`).
- Show green online dot badge only if player UUID is also in `activePlayers`.
- Show a Bedrock controller icon badge if `entry.isBedrock == true`.
- `sessionPlayers` empty AND server not running → existing empty state ("No players yet").
- `sessionPlayers` not empty AND server not running → show cards with grey subtitle
  "Last session" below the username.
